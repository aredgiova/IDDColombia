## NEXT.JS

Utiliza las capacidades nativas de Next.js siempre que sea posible.

Prioriza:

- Server Components;
- Server Side Rendering cuando corresponda;
- Static Generation cuando corresponda;
- Incremental Static Regeneration cuando corresponda;
- Route Handlers;
- Server Actions para operaciones internas cuando sean útiles;
- `next/image`;
- `next/font`;
- Metadata API.

Evita utilizar `"use client"` innecesariamente.

Los componentes deben ser Server Components por defecto.

Utiliza Client Components solamente cuando exista:

- interacción;
- estado;
- eventos;
- hooks del navegador;
- APIs del navegador;
- librerías que requieran ejecución del lado cliente.

Quiero minimizar el JavaScript enviado al navegador.

## VERCEL

Todo debe estar optimizado para:

GitHub → Vercel → Producción.

La aplicación debe funcionar correctamente en:

- Development;
- Preview;
- Production.

No utilices rutas absolutas locales.

No dependas de un servidor ejecutándose permanentemente.

No utilices el filesystem local como almacenamiento persistente.

No crees `vercel.json` salvo que exista una necesidad específica.

Vercel debe reconocer automáticamente el proyecto Next.js.

Utiliza Node.js Runtime como runtime principal.

No utilices Edge Runtime salvo que exista una razón clara.

## API

Aunque inicialmente el sitio pueda tener poca lógica de backend, deja preparada la arquitectura para API.

Utiliza:

`src/app/api/`

Crea inicialmente:

GET `/api/health`

que devuelva:

{
  "success": true,
  "status": "ok",
  "service": "web-api"
}

Posteriormente podremos crear endpoints bajo:

`/api/v1/`

Ejemplo:

`/api/v1/users`

`/api/v1/products`

`/api/v1/contact`

`/api/v1/auth`

dependiendo de las necesidades del proyecto.

## FORMATO DE RESPUESTAS API

Cuando creemos APIs utiliza una respuesta consistente.

Éxito:

{
  "success": true,
  "data": {},
  "message": null
}

Error:

{
  "success": false,
  "data": null,
  "message": "Descripción del error",
  "error": {
    "code": "ERROR_CODE"
  }
}

Utiliza correctamente códigos HTTP.
